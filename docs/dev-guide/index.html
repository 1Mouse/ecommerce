Current backend shape

Modular monolith with explicit contracts and boring boundaries

This project uses Express without letting Express become a pile of scattered handlers. Each feature owns its routes, schemas, controllers, services, repositories, models, tests, Bruno requests, and documentation. The goal is clarity first: every public API path is searchable, every layer has one job, and tests verify behavior through HTTP.

MongoDB Mongoose models and repositories
Vitest Integration tests through public APIs
Bruno Manual API docs synced from route manifests

Architecture

Modular Monolith

One deployable Node API, split internally by business modules. We avoid microservice complexity while still keeping clean module boundaries.

Feature Locality

Feature code lives together under src/modules. Auth code stays in auth. User/address code stays in users. Country reference data stays in countries.

Explicit Contracts

Every route has a manifest entry with full path, method, auth requirement, and validation schemas. Route discovery is no longer split between app.ts and routers.

Dependency Direction

Outer HTTP layer drives inner application behavior
ClientFrontend, Bruno, curl, tests, mobile app.
RoutesMap manifest operations to middleware and controller methods.
ControllerHTTP input/output only. No persistence rules.
ServiceApplication workflow and business decisions.
RepositoryPersistence boundary. Returns plain app objects.
ModelMongoose schemas, indexes, timestamps.

Request Flow

Example: POST /api/v1/auth/refresh

Manifest path to service behavior
Manifestauth.manifest.ts declares /api/v1/auth/refresh.
Routeauth.routes.ts uses manifest path and body schema.
ControllerReads validated body and sends response envelope.
ServiceValidates refresh token, rotates it, creates new tokens.
RepositoryReads/revokes refresh-token records by hash.
MongoDBStores only refresh token hashes, never raw tokens.

Modules

auth

Signup, login, refresh-token rotation, logout, logout-all, access-token middleware, password hashing, JWT signing, and refresh-token persistence.

countries

Route Manifests

Why They Exist

Express normally hides the full route across app.use('/prefix') and router.post('/child'). Manifests keep the full public route in one searchable place.

Searchable paths Version metadata Schema metadata

Route Identity

The name field is a stable operation identifier. The path can change for versioning, but auth.login still means the login operation.

Manifest Example

Operation-first: one method plus one path 
export const authManifest = {
  refresh: defineRoute({
    name: "auth.refresh",
    brunoVar: "authRefreshPath",
    version: "v1",
    method: "post",
    path: "/api/v1/auth/refresh",
    auth: "public",
    bodySchema: refreshBodySchema,
  }),
} as const;

Versioning Rule

Keep full paths explicit, like /api/v1/auth/refresh. When v2 exists, add v2 manifest entries instead of hiding versions in string builders. Public contracts should be easy to grep.

Layer Duties

Part Purpose Must Not Do
*.manifest.tsDeclare route contract metadata: name, version, method, path, auth, request schemas, Bruno variable.Run code, query DB, or call controllers.
*.routes.tsRegister Express routes using manifest paths and route-level middleware.Contain business rules.
*.controller.tsTranslate HTTP requests to service calls and service results to response envelopes.Call repositories directly or know Mongoose details.
*.service.tsOwn workflows, business decisions, cross-module service calls, and error semantics.Import Express request/response objects.
*.repository.tsHide Mongoose queries and return plain app objects with id, not raw documents.Contain HTTP behavior or response formatting.
*.model.tsDefine Mongoose schema, collection name, timestamps, indexes, and Mongo constraints.Run application workflows.
*.schema.tsValidate request body, params, and query using Zod strip mode.Check database existence. That is service-level semantics.

Soft Deletes

Normal reads exclude records with deletedAt. Deletes set deletedAt and return a 200 envelope.

Timestamps

Mongoose manages createdAt and updatedAt with timestamps: true. The app manages deletedAt.

Index Discipline

Indexes exist only for unique constraints, frequent lookups, and TTL cleanup. Do not index every foreign key by default.

Auth Model

Access Token

JWT created with jose. It is stateless and short-lived: 15 minutes. Middleware verifies signature, expiry, and type: access.

Refresh Token

Opaque random string, not JWT. We store only SHA-256 hashes in refreshTokens. Lifetime is 30 days.

Password

Passwords use bcryptjs. Raw passwords never leave the request workflow and are never stored.

Logout Reality

Logout revokes refresh tokens. Existing stateless access tokens may work until their 15-minute expiry. This is a deliberate tradeoff for simpler, faster protected routes.

Testing

Testing Philosophy

Tests verify behavior through public HTTP interfaces. They do not call private services, repositories, or Mongoose models directly.

Current Stack

Vitest runs integration-style tests against the Express app and a real isolated MongoDB test database.

Test Layout

Public behavior over implementation details 
test/helpers/
  test-db.ts       # isolated Mongo test database
  test-server.ts   # starts app on random port
  http.ts          # requestRoute helper using manifests

test/auth-users/
  health-countries.test.ts
  auth.flow.test.ts
  users-addresses.flow.test.ts

TDD Rule

Do not write all tests first. Use vertical slices: one behavior test, minimal implementation, refactor, repeat. New features start with a failing public-interface test.

Add Or Change A Route

Edit the feature *.manifest.ts first. The public route contract should be the first thing you can search for.

Wire Express

Use the manifest entry in *.routes.ts with auth middleware and validation middleware.

Implement Behavior

Controller calls service. Service calls repositories or another module's service. Repository talks to Mongoose.

Add Tests

Write or update Vitest integration tests through requestRoute and route manifests.

Sync Bruno

If paths changed, run pnpm sync:bruno-routes, then update request bodies/scripts if needed.

Architecture Guardrails

Do Not

  • Do not let controllers call repositories directly.
  • Do not let controllers call other controllers.
  • Do not put business rules in route files.
  • Do not expose Mongoose documents outside repositories.
  • Do not query another module's repository from a service. Use that module's service.
  • Do not store raw refresh tokens or raw passwords.
  • Do not add indexes just because a field exists.
  • Do not hardcode API paths in tests when a manifest exists.

Do

  • Start route changes in *.manifest.ts.
  • Keep modules feature-local under src/modules.
  • Use Zod for request shape validation.
  • Use services for semantic/business validation.
  • Return consistent response envelopes.
  • Use repositories as the persistence boundary.
  • Test behavior through HTTP with Vitest.
  • Run pnpm typecheck and pnpm test before considering work done.
