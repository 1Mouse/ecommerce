Backend persistence lesson 001

MongoDB stores documents. Mongoose gives your app a disciplined way to use them.

Your ecommerce backend needs a database layer that is practical now and swappable later. This lesson answers three beginner questions: what MongoDB stores, whether schemas are mandatory, and what belongs in the infrastructure layer.

Project: ecommerce API Stack: Node, Express, TypeScript, Mongoose Current file: src/infrastructure/database/mongodb.ts

1. What MongoDB Stores

Database

A database is a container for collections. In an ecommerce app, one database might hold users, products, orders, sessions, and carts.

Collection

A collection is a group of documents. It is roughly analogous to a relational table, but documents in the same collection can have different fields by default.

Document

A document is the actual record MongoDB stores. MongoDB stores records as BSON documents, a binary format similar to JSON with extra data types.

{ _id: ObjectId("..."), email: "customer@example.com", role: "customer", addresses: [ { city: "Cairo", country: "EG" } ], createdAt: ISODate("2026-05-30T00:00:00Z") }

Key point: MongoDB can store nested objects and arrays inside a single document. That is why document modeling starts from access patterns, not table normalization.

Automatic id: each normal MongoDB document needs a unique _id. If you do not provide one, the driver usually creates an ObjectId.

Limit: a single BSON document has a maximum size of 16 MiB, so huge unbounded arrays are a modeling smell.

2. Is A Schema Mandatory?

MongoDB itself

No schema is mandatory by default. A collection can contain documents with different fields and different field types.

You can add database-level schema validation later when the shape is established and you want MongoDB itself to reject bad inserts or updates.

Mongoose

Mongoose starts with a schema. A schema maps to a collection and defines the shape Mongoose expects for documents in that collection.

The schema can be strict or loose. By default, Mongoose strict mode keeps unknown fields from being saved through that model.

MongoDB schema: optional database rule.

Mongoose schema: application-side contract for a model.

TypeScript type: compile-time help only, gone at runtime.

Common trap: Mongoose validation is not the same as MongoDB validation. If some other tool writes directly to MongoDB, it can bypass Mongoose. Database validation is needed when the database must defend itself.

3. What Mongoose Adds

Schema

Defines fields, types, defaults, timestamps, indexes, validators, strict behavior, and collection options.

Model

A model is compiled from a schema. It is the object you call to create, find, update, delete, and aggregate documents.

Document

A document is one model instance with Mongoose behavior attached, such as validation, save, casting, getters, and virtuals.

Validation caveat: validation runs before save, but update validators are off by default unless enabled on update operations.

Unique caveat: Mongoose unique is not a validator. It helps create a MongoDB unique index. Duplicate errors come from the database index.

4. The Infrastructure Layer

The infrastructure layer is where your app talks to external systems. MongoDB, Mongoose, Docker, payment gateways, email providers, and file storage are infrastructure concerns. Your business logic should not depend directly on them.

In your repo today: connectMongo belongs in infrastructure because it opens a Mongoose connection and configures driver options.

Mongoose schema/model: infrastructure, because they import Mongoose and encode database storage details.

Repository implementation: infrastructure, because it translates between domain objects and database documents.

Repository interface: not infrastructure. It belongs inward, near the application/domain code that needs persistence.

5. Tiny Mental Model

MongoDB: "I store BSON documents in collections. I am flexible unless you add validation rules."

Mongoose: "I give your Node app schemas, models, casting, validation, hooks, indexes, and connection management."

Infrastructure layer: "I hide Mongoose behind adapters so the rest of the app does not become database-shaped."
